# 採用者管理システム 要件定義書

## 1. プロジェクト概要

### 1.1 背景
- 企業が従来、楽々ライブラリ（豊里システムソリューション製）を使用して採用者情報をPDFで管理していた
- 楽々ライブラリの販売終了に伴い、新しいシステムへの移行が必要
- 既存の運用方法を踏襲しつつ、モダンな技術で再構築する

### 1.2 目的
- 採用者の情報（履歴書、職務経歴書、面接記録など）をPDF形式で効率的に管理
- 直感的な操作で誰でも使えるUIを提供
- 大容量（TB超）のデータを安全かつ効率的に保管・検索できるシステムを構築

## 2. 機能要件

### 2.1 コア機能（楽々ライブラリの踏襲）

#### 2.1.1 階層構造によるドキュメント管理
- **書庫 → キャビネット → バインダ → ドキュメント** の4階層構造
- 採用者管理における構造例：
  - 書庫：マイライブラリ
  - キャビネット：年度別（2024年度採用、2025年度採用など）
  - フォルダ：部署別・職種別（エンジニア、営業、管理部門など）
  - ドキュメント：個別の採用者PDF（履歴書、職務経歴書など）

#### 2.1.2 ドキュメント表示機能
- PDFビューア機能
  - ページ送り/戻り
  - 見開き表示対応
  - ズーム機能
  - 回転機能
- 付箋紙機能（メモ・コメント追加）
- マーカー機能（重要箇所のハイライト）

#### 2.1.3 検索機能
- ドキュメント名での検索
- フォルダ横断検索
- 全文検索（将来対応）

#### 2.1.4 アップロード機能
- ドラッグ&ドロップ対応
- 複数ファイル一括アップロード
- PDF以外の形式対応（Word、Excel、画像）

#### 2.1.5 ダウンロード機能
- 個別ファイルのダウンロード
- フォルダ単位の一括ダウンロード（ZIP化）

### 2.2 採用者管理特有の機能

#### 2.2.1 採用者情報管理
- 採用者ごとにフォルダを作成
- 以下のドキュメントを格納：
  - 履歴書PDF
  - 職務経歴書PDF
  - 面接評価シートPDF
  - 適性検査結果PDF
  - 内定通知書PDF
  - その他関連資料

#### 2.2.2 メタデータ管理
- 採用者名
- 応募職種
- 応募日
- 選考ステータス（書類選考中、1次面接、2次面接、内定、不採用など）
- 担当採用担当者
- タグ（スキル、経験年数など）

#### 2.2.3 アクセス権限管理
- 人事部：全データへのアクセス
- 部署責任者：該当部署の採用者データのみ閲覧
- 面接官：担当した採用者のデータのみ閲覧

#### 2.2.4 採用プロセス管理
- 選考ステータスの更新
- 面接スケジュール管理
- 選考履歴の記録

## 3. 非機能要件

### 3.1 性能要件
- **データ容量**: TB超のデータを扱える設計
- **レスポンス時間**:
  - ドキュメント一覧表示: 2秒以内
  - PDF表示: 3秒以内（10MBのファイル）
  - 検索結果表示: 5秒以内
- **同時アクセス数**: 100ユーザー程度を想定

### 3.2 セキュリティ要件
- 個人情報保護法に準拠
- アクセスログの記録
- 定期的なバックアップ
- データ暗号化（保存時・通信時）
- 不採用者データの自動削除（一定期間経過後）

### 3.3 可用性要件
- 稼働率: 99.5%以上
- バックアップ: 日次
- 災害対策: 地理的に離れた場所へのバックアップ

### 3.4 運用要件
- マニュアル不要の直感的UI
- モバイル対応（タブレット・スマートフォン）
- 主要ブラウザ対応（Chrome、Edge、Safari）

## 4. 技術的課題

### 4.1 ストレージ問題
**課題**: TB超のPDFファイルをどこに保存するか

**検討事項**:
1. コスト（初期費用・運用費用）
2. スケーラビリティ（容量の拡張性）
3. パフォーマンス（読み込み速度）
4. セキュリティ（データ保護・暗号化）
5. バックアップ・災害対策
6. 法規制対応（個人情報保護法、GDPR等）

**候補となるストレージソリューション**:
- クラウドストレージ（AWS S3、Azure Blob Storage、Google Cloud Storage）
- オンプレミスストレージ（NAS、SAN）
- ハイブリッド構成

→ 詳細は `02_storage_design.md` を参照

### 4.2 データ移行
- 既存の楽々ライブラリからのデータ移行計画
- フォルダ構造の維持
- メタデータの移行

### 4.3 スケーラビリティ
- データ量の増加に対応
- ユーザー数の増加に対応
